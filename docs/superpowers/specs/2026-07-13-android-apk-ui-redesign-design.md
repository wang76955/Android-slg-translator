# Android APK 全新 UI 设计规格

## 1. 目标与范围

本次重设计面向普通安卓玩家，覆盖“选择游戏 APK → 扫描文本 → DeepSeek 翻译 → 重新打包 → 安装或保存”的完整主流程。首版只支持 DeepSeek，用户在首次启动时提供 API Key。高级模型参数、多供应商和专业文本编辑不在首版范围内。

## 2. 设计方向

确定方向为“玩家工坊”。物理场景是：玩家晚上靠在家中沙发上，希望快速处理一款想玩的剧情游戏；界面像玩家社区里一间整洁、可信的小工坊，而不是开发者控制台。

颜色策略为 Restrained：中性表面为主，苔藓橄榄绿承载主操作，明亮黄褐只承载品牌图标和少量完成状态。避免落入“森林绿配奶油底”的常见 AI 视觉套路：浅色主背景使用纯白，温度由品牌色、插图和文案表达。

## 3. 信息架构

底部导航包含三个目的地：

- **首页**：开始新翻译、继续未完成任务、查看最近成果。
- **作品**：已生成 APK 和历史任务。
- **我的**：DeepSeek API Key、主题、默认存储位置和帮助。

紧凑屏幕使用 Material 3 Navigation Bar；平板等展开宽度切换为 Navigation Rail。任务内部页面使用顶部应用栏与系统返回/预测性返回，不重复显示底部主导航。

## 4. 核心流程

### 4.1 选择 APK

首页主文案为“让喜欢的故事，用中文继续。”主操作面板中只提供“选择 APK 文件”。文件返回后展示游戏图标、文件名和大小，然后自动执行类型与存储空间检查。

### 4.2 扫描

扫描页使用线性进度条和普通语言状态，例如“正在查找剧情文本”。可展开的“处理详情”才显示文件路径和技术日志。不支持时立即停止，解释原因并保留重新选择入口。

### 4.3 翻译确认

在发起 API 请求前，展示检测到的句数、预估消耗、目标语言与文件输出位置。主按钮为“开始翻译”，高级数据不成为开始前的必填决策。

### 4.4 翻译与打包

显示整体百分比、已完成句数和预计剩余时间。“暂停”为次要按钮，“取消任务”放在更多菜单并需二次确认。翻译完成后自动进入打包阶段，不要求用户理解中间产物。

### 4.5 完成

完成页展示游戏图标、“汉化完成”、翻译句数、耗时、生成文件大小和保存位置。全宽填充按钮“立即安装”是主操作，轮廓按钮“保存 APK”为次操作。安装失败不删除生成文件。

## 5. 首次启动与 API Key

首次启动包含两个页面：

1. 欢迎页用一句话解释产品：“选择游戏 APK，自动生成可安装的中文版本。”唯一主操作为“开始设置”。
2. DeepSeek 设置页包含 API Key 输入、显隐切换、粘贴按钮和“如何获取”说明。“继续”先验证密钥，通过后才完成引导。

API Key 只保存在设备本地，使用 Android Keystore 保护的加密存储，日志不得记录密钥全文。无有效密钥时可浏览已有作品，但开始新翻译时必须进入设置。

## 6. 页面与组件规则

- 使用 Material 3 标准的 Top App Bar、Navigation Bar/Rail、Filled/Tonal/Outlined Button、Text Field、Linear Progress Indicator、Snackbar 和 Dialog。
- 同一屏只突出一个填充式主按钮；不堆叠 FAB，本产品首版默认不使用 FAB。
- 组件圆角使用 16–20dp 的统一层级，触控区域至少 48×48dp，相邻触控目标间隔至少 8dp。
- 界面边到边绘制，正确处理状态栏、导航栏、刘海和软键盘 insets。
- 文字使用 Material 字号角色与 `sp`，不按页面随意指定像素字号。标签和按钮优先使用 Roboto/系统字体。
- 任务加载用内容骨架或线性进度，不在主内容中央长时间显示旋转器。
- 短暂成功反馈使用 Snackbar；只有不可逆决策使用 Dialog。

## 7. 动效

状态变化使用 150–250ms 的 Material 过渡：页面阶段切换使用 fade-through，详情展开使用标准尺寸动画。不使用编排式首屏动画或夸张庆祝特效。系统开启“移除动画”时改用即时切换或短交叉淡化。

## 8. 异常与恢复

| 情况 | 界面行为 | 主操作 |
| --- | --- | --- |
| 非 APK 文件 | 说明支持的文件类型，不进入扫描 | 重新选择 |
| 不支持的游戏 | 说明未找到可处理内容 | 选择其他 APK |
| 网络中断 | 自动暂停并保存已完成批次 | 继续翻译 |
| API Key 无效 | 保留任务并显示密钥问题 | 更新 API Key |
| DeepSeek 余额不足 | 保留进度并解释余额不足 | 前往充值说明 |
| 存储不足 | 在开始前显示所需空间 | 释放空间后重试 |
| 应用被系统回收 | 下次启动恢复任务快照 | 继续上次任务 |
| 安装权限缺失 | 跳转系统“安装未知应用”授权页 | 允许后继续安装 |
| 部分文本失败 | 保留成功结果并列出失败数量 | 仅重试失败项 |

错误文案不向普通用户暴露原始异常堆栈或不可解释的错误码。诊断信息只存在可复制的“处理详情”中。

## 9. 状态与数据流

任务状态明确为 `selected`、`scanning`、`ready`、`translating`、`paused`、`packaging`、`completed` 或 `failed`。主界面只读取任务摘要；扫描、API 批次、打包和安装权限分别作为独立边界，通过可持久化的任务事件更新状态。每个翻译批次成功后写入检查点，以支持暂停、应用重启和部分重试。

## 10. 验收标准

1. 新用户无需理解 APK 解包、模型参数或技术日志即可完成翻译。
2. 从选择文件到开始翻译，用户最多做三个明确决策。
3. 浅色与深色主题都是完整语义配色，并默认跟随系统。
4. 正文对比度至少达到 WCAG AA；所有交互触控目标至少 48dp。
5. 系统字体缩放、横屏、显示刘海、软键盘和移除动画均不造成遮挡或文本溢出。
6. 任务可暂停、恢复，并能在应用重启后从最近检查点继续。
7. 完成页同时提供“立即安装”和“保存 APK”，且安装失败不删除文件。
8. API Key 仅保存在设备本地，可替换或删除，不出现在日志中。
9. 每种可预期失败状态都包含普通语言说明和至少一个可执行的下一步。

## 11. 测试范围

- 单元测试：任务状态转换、检查点恢复、异常到用户文案的映射。
- 集成测试：文件选择、DeepSeek 密钥验证、断网恢复、本地加密存储和安装权限往返。
- UI 测试：首次引导、完整五步主流程、暂停/继续、完成页两个出口和底部导航。
- 视觉回归：紧凑宽度手机、平板、横屏、浅色/深色、默认/大字体。
- 真机测试：预测性返回、边到边 insets、文件选择器、安装未知应用授权和系统主题切换。
