# Android UI 系统与动画覆盖升级设计

## 1. 状态与范围

- 状态：已获用户确认，进入实现计划前的设计归档阶段。
- 日期：2026-08-09。
- 平台：Android，现有 React WebView 注入层加 Java 原生桥接。
- 目标：在不改变业务流程、数据结构、React 控件和 Java 插件接口的前提下，升级所有可见页面的 UI、状态表达、动画、性能和可访问性。
- 本文只定义设计和验收标准，不直接修改 APK 或业务代码。

## 2. 已确认事实

1. 可见 UI 主要由 `apk-work/ui-redesign/patch_workshop_ui.py` 注入到现有 React WebView。
2. 原始 React 控件仍然承担文件选择、扫描、翻译、打包、安装和设置保存等业务行为。
3. 可见层通过事件桥接触发原始控件，不能移动、克隆或替换 React 管理的节点。
4. 当前 `test_workshop_patch.py` 的 64 项契约测试全部通过。
5. 当前工作区同时存在旧蓝色流程截图和较新的绿色工坊流程截图，截图不能直接视为同一版本的前后对比。
6. 当前样式已经包含浅色、深色、触控目标、底部弹层和部分状态动画，但仍存在全块重绘、持续 shimmer、列表动画缺口和真实帧率证据不足等问题。

## 3. 推测与未知

### 推测

- 当前绿色工坊视觉是后续版本的目标方向，但部分未提交 APK 产物可能没有使用最新生成资源。
- 任务进度变化可能触发状态区域重建，因此需要在实现时用行为测试确认 DOM 更新范围。

### 未知

- 当前连接设备上安装的 APK 与最新源码之间的精确对应关系，需要重新构建、安装和记录版本指纹后确认。
- 60FPS 是否达到不能由契约测试推断，必须用真实设备帧统计和视觉检查确认。
- 横屏、平板、系统字体放大和深色模式的最终表现需要在生成 APK 上实测。

## 4. 目标与非目标

### 目标

- 建立统一的 Material 3 风格轻量设计系统。
- 让首页、任务流程、安装包、设置和弹层使用同一套视觉语言。
- 让每个任务状态有清晰的主说明、下一步操作和可展开详情。
- 覆盖加载、空状态、错误、恢复、完成、删除中和删除失败等边界状态。
- 使用轻量动画表达状态变化，避免装饰性动画影响效率。
- 支持深色模式、系统字体放大、系统 Back、减少动画和不同屏幕宽度。
- 在真实 Android 设备上验证动画帧率、滚动、进度更新和内存清理。

### 非目标

- 不迁移到 Jetpack Compose。
- 不重写现有 React 业务流程、Java 桥接或数据结构。
- 不移动或克隆 React 管理的文件选择、开始翻译和安装控件。
- 不把 Remotion 作为 APK 运行时 UI 动画引擎。Remotion 适合生成视频或演示素材，不作为 WebView 交互动画依赖。
- 不在缺少 DSN、隐私策略和网络策略的情况下强行接入 Sentry。
- 不为了视觉效果引入大体积图片、持续背景动画或默认毛玻璃。

## 5. 总体架构

### 5.1 可见层与业务层

可见层继续由注入运行时负责：

- 页面结构和组件样式。
- 当前任务状态的可视化。
- 动画和交互反馈。
- 空状态、错误和恢复文案。
- 安装包列表、设置菜单和弹层的可见容器。

业务层继续由现有 React 和 Java 桥接负责：

- APK 文件选择和已安装应用选择。
- APK 扫描、文本提取、翻译、打包和安装。
- API Key、模型、存档、缓存和安装包数据。
- 原始任务恢复和持久化。

可见层只能通过现有事件桥接触发业务控件，例如向已存在的 React 按钮派发冒泡的 `MouseEvent("click")`。禁止把 React 节点直接插入可见壳层。

### 5.2 状态模型

任务状态固定为：

```text
idle
scanning
empty
ready
translating
patching
completed
failed
```

每个状态必须提供：

- 顶部上下文和返回行为。
- 普通语言的当前状态说明。
- 主操作或恢复操作。
- 可选的处理详情。
- 可访问的状态播报。

状态改变时只更新变化区域，不重建整个任务壳层。任务壳层、文件摘要、进度区和操作区使用稳定节点；翻译进度只更新数字、进度条和最近状态。

### 5.3 导航边界

- `idle` 显示底部导航。
- `scanning`、`empty`、`ready`、`translating`、`patching`、`completed`、`failed` 隐藏底部导航。
- 设置和安装包页面使用同一套顶部返回栏。
- 弹层打开时，Android Back 先关闭弹层。
- 任务状态返回首页时保留已选择文件和可恢复信息。
- 不覆盖系统预测返回手势。
- 紧凑宽度使用底部导航，展开宽度使用侧边导航或导航栏。

## 6. 视觉系统

### 6.1 品牌气质

产品应像玩家社区里一间整洁、可靠的汉化工坊，而不是开发者控制台或游戏宣传页。

关键词：

- 温暖
- 可靠
- 简洁
- 有轻微手作感
- 不使用夸张游戏特效

### 6.2 颜色角色

使用 Material 3 语义角色，不在组件内散落原始颜色值：

- `primary`：克制橄榄绿，用于主要操作和当前选中。
- `onPrimary`：主色上的高对比文字和图标。
- `surface`：内容表面。
- `surfaceVariant`：辅助面板和输入区域。
- `onSurface`：正文。
- `onSurfaceVariant`：辅助文字。
- `outline`：边界和分隔。
- `error`：错误和破坏性操作。
- `success`：完成和可继续状态。
- `warning`：空间、权限和风险提示。

浅色和深色主题分别定义完整角色，不使用简单反色。WebView 需要保留兼容性回退值，再使用当前支持的高级颜色表达式，避免旧 WebView 因颜色函数不支持而失去可读性。

设计限制：

- 页面不使用大面积装饰性渐变。
- 不默认使用 `backdrop-filter`。
- 不使用光晕、点阵和持续变化背景作为主视觉。
- 不依靠颜色作为唯一状态提示。

### 6.3 字体与间距

- 优先使用 Roboto、Noto Sans SC 或系统无衬线字体。
- 页面标题使用紧凑的标题层级，不使用展示型字体。
- 正文、按钮和标签必须支持系统字体放大。
- 页面边距默认为 16dp，展开宽度增加到 24dp。
- 区块间距使用 16dp，内部间距使用 8dp、12dp、16dp。
- 触控目标不小于 48dp，相邻目标至少保留 8dp 间距。

### 6.4 形状与层级

- 普通卡片：16dp 圆角。
- 输入框和列表项：12dp 圆角。
- 弹层：24dp 顶部圆角。
- 使用 tonal elevation 和微阴影表达层级。
- 禁止多层卡片嵌套。
- 同一页面只保留一个视觉主操作。

## 7. 页面设计

### 7.1 空闲首页

首页只回答“现在要选择什么”。

- 顶部显示应用名称和当前页面上下文。
- 使用紧凑品牌说明，不使用占据大面积的宣传 Hero。
- 主操作为“选择应用或 APK”。
- 有未完成任务时显示可恢复任务摘要。
- 没有任务时显示简洁说明和主操作。
- API Key、模型、日志和内部路径不出现在首页。

### 7.2 APK 来源选择

使用统一底部弹层，提供：

- 选择 APK 文件。
- 从已安装应用选择。
- 取消。

已安装应用列表支持搜索、加载、空状态、失败重试和从文件选择回退。显示应用名称和包名，不能只显示原始 URI。

### 7.3 扫描

- 显示文件名称、文件类型和已选择状态。
- 使用线性进度和普通语言状态。
- 详情默认折叠，日志和内部路径只放入详情。
- 不显示大型旋转图标。
- 不伪造精确百分比。

### 7.4 无可翻译内容

- 解释没有找到可处理文本的原因。
- 拆分 APK 明确说明当前只检查了基础 APK。
- 主操作为重新选择应用或 APK。
- 不把内部诊断码放在首屏。

### 7.5 翻译准备就绪

- 显示文件名称、可翻译文件数量和语言方向。
- 任务模式放在摘要或折叠设置中。
- “开始翻译”为唯一主操作。
- 文件列表默认折叠，避免大量文件撑高页面。
- 兼容性预检阻断时，主操作改为修复、切换或重新选择，而不是显示不可用的开始按钮。

### 7.6 翻译中与生成中

- 显示阶段标签、当前文件、进度和最近状态。
- 进度变化只更新稳定节点。
- 不重复播放卡片入场动画。
- 保留现有暂停、继续或恢复行为；没有现有业务支持的操作不在 UI 层新增。
- 生成 APK 阶段明确说明正在生成可安装文件。

### 7.7 完成

- 结果摘要显示游戏名称、完成数量、生成文件和文件大小。
- “立即安装”为主操作。
- “保存 APK”为次要操作。
- 安装失败不删除生成文件。
- 结果页面不展示构建日志。

### 7.8 错误与恢复

错误按普通用户可理解的原因分类：

- 文件格式不支持。
- 没有可翻译内容。
- 网络或翻译服务失败。
- API Key 无效。
- 手机空间不足。
- APK 生成失败。
- 安装权限不足。

每个错误必须包含发生了什么、下一步可以做什么和至少一个可执行操作。原始异常放入可展开详情。

### 7.9 安装包页面

- 列表显示名称、文件大小和生成时间。
- 保存和删除使用统一按钮风格。
- 删除只锁定当前条目，不阻塞整页。
- 列表加载、空状态、读取失败、删除中和删除失败均有独立显示。
- 刷新失败时保留旧列表，避免整页闪空。

### 7.10 我的与设置子页面

设置首页使用分组列表：

- 翻译服务。
- 存档转移。
- 清理安装包与旧缓存。
- 关于。

翻译服务页面保留现有供应商、模型、API Key、显示隐藏、验证和本地保存行为。存档页面保持游戏选择、备份列表、分享导入和恢复行为。清理页面显示可释放空间和文件数量，并在破坏性操作前确认。关于页面只展示版本和支持信息。

## 8. 动画设计

### 8.1 时长

- 按钮反馈：100 至 120ms。
- 状态切换：160 至 200ms。
- 卡片进入：180 至 220ms。
- 底部弹层：220 至 260ms。
- 列表新增或删除：180 至 240ms。
- 进度变化：200 至 260ms。
- 页面返回：160 至 200ms。

普通交互不超过 400ms。动画表达状态，不让用户等待动画。

### 8.2 状态覆盖矩阵

| 路径 | 动画 | 约束 |
| --- | --- | --- |
| `idle -> scanning` | 文件摘要淡入，状态区轻微上移 | 只播放一次 |
| `scanning -> empty` | 状态区 fade-through | 主操作位置稳定 |
| `scanning -> ready` | 详情和摘要淡入 | 不重建整个壳层 |
| `ready -> translating` | 进度区原位展开 | 不重复播放卡片入场 |
| `translating -> patching` | 阶段标签和说明切换 | 只更新变化节点 |
| `patching -> completed` | 进度区淡出，完成摘要淡入 | 数字短暂过渡 |
| 任意状态 -> failed | 错误区淡入 | 操作按钮不跳动 |
| 来源选择 | 遮罩淡入，底部面板上移 | Back 反向关闭 |
| 安装包新增 | 行淡入并轻微上移 | 不刷新整页 |
| 安装包删除 | 当前行局部 loading，完成后淡出 | 失败保留并可重试 |
| 存档导入或删除 | 当前行局部更新 | 不影响其他行 |
| 完成 -> 系统安装 | 应用内完成反馈后进入系统 | 系统页由 Android 控制 |

### 8.3 动画技术限制

- 优先使用 `transform`、`opacity` 和进度宽度变化。
- 不动画化大面积阴影、模糊、过滤器和复杂布局高度。
- 不使用持续运行的大面积背景动画。
- shimmer 默认关闭或缩短为启动提示。
- 状态相同时不重播动画。
- 所有 timer、observer、Wake Lock 和弹层监听器必须在退出状态时清理。

### 8.4 减少动画

系统启用减少动画时：

- 状态即时切换或短淡入。
- 卡片取消位移。
- 列表直接更新。
- 进度直接更新到目标值。
- 弹层保留透明度变化或即时显示。
- 关闭 shimmer 和数字计数动画。

## 9. 性能设计

### 9.1 更新模型

- 任务壳层、文件摘要、进度区、详情区和操作区使用稳定节点。
- `MutationObserver` 只保留一个，并使用防抖和 `requestAnimationFrame` 合并更新。
- `snapshotKey` 未变化时不触发渲染。
- 翻译进度不通过 `replaceChildren` 重建整块任务卡。
- 日志默认不渲染，展开详情时再显示。
- 长列表避免不必要的全部节点重建。

### 9.2 低端设备策略

- 移除默认毛玻璃。
- 限制阴影层级和持续动画数量。
- 只保留必要的 SVG 图标。
- 任务期间不渲染隐藏的旧主界面。
- 动画掉帧时先移除 shimmer、模糊和阴影动画，再降级为透明度或即时切换。
- 不通过隐藏必要状态或缩小文字来掩盖性能问题。

### 9.3 性能验收

- 真机首页滚动、按钮点击和弹层打开无明显卡顿。
- 翻译和生成期间进度更新不闪烁、不重复入场。
- `adb shell dumpsys gfxinfo` 记录关键动画帧耗时。
- 以 16.7ms 帧预算观察关键动画，不在未测量时宣称达到 60FPS。
- 记录与基线的掉帧差异，不能因 UI 升级显著退化。
- 检查没有重复 Overlay、重复监听器或未释放 Wake Lock。

## 10. 可访问性与兼容性

- 所有控件触控目标至少 48dp。
- 所有图标按钮提供可读标签和必要的 tooltip/title。
- 状态使用文字、图标和结构共同表达，不只使用颜色。
- 使用 `aria-live` 播报任务状态、错误和删除结果。
- 支持系统字体放大，长文件名使用省略但详情可查看。
- 支持浅色、深色和系统减少动画。
- 正确处理状态栏、导航栏、显示切口和软键盘 inset。
- 系统 Back 优先关闭当前弹层，再返回任务或首页。
- 检查 CSS 高级颜色函数和 `:has` 等能力的 WebView 兼容回退。
- 横屏和平板不强制使用手机底部导航。

## 13. 完成标准

只有同时满足以下条件，才可宣称 UI 升级完成：

1. 所有可见页面使用统一视觉 token 和组件状态。
2. 旧蓝色流程不再出现在最终 APK 的主路径。
3. 任务状态、弹层、列表、错误和恢复路径都有明确动画或明确的即时降级行为。
4. 翻译进度不会整块重建任务卡，也不会重复播放入场动画。
5. 安装包和存档列表支持行级新增、删除、失败和重试反馈。
6. 深色模式、减少动画、系统字体放大和 Android Back 实测通过。
7. 64 项现有契约测试和新增 UI 动画测试全部通过。
8. 真实 APK 已构建、签名、安装并启动成功。
9. 真机帧统计和截图证据已保存。
10. 未验证的 60FPS、横屏或平板结果不得写成已完成。
