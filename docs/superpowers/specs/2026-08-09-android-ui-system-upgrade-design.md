## 1. 设计决策

### 1.1 推荐方案 B

不迁移到 Jetpack Compose，不改 React 业务流程、Java 桥接接口和数据结构，在现有 WebView 可见层完成结构性升级。

第二轮必须产生明显视觉变化：

- 首页改为紧凑三步任务引导，压缩品牌区。
- 导航改为标准 Material 表面贴边栏；选中态使用小型 tonal indicator。
- 去除默认持续毛玻璃、点阵、光晕和大面积装饰渐变。
- 设置、安装包、存档和错误页统一返回栏、列表行和状态反馈。
- 进度、列表、弹层和错误恢复都采用局部更新和有限动画。

### 1.2 方案对比

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| A：轻量换肤 | 只改颜色、圆角和按钮 | 视觉变化不足，不采用 |
| B：结构性 WebView 升级 | 改变页面层级、导航、稳定壳层和行级反馈，不改变业务边界 | **采用** |
| C：Compose/原生重写 | 重建 Android UI 和导航 | 违反当前架构约束，拒绝 |

## 2. 事实、推测和未验证项

### 2.1 已确认事实

1. 可见 UI 主要由 `apk-work/ui-redesign/patch_workshop_ui.py` 生成并注入 React WebView。
2. 原始 React 控件继续负责文件选择、扫描、翻译、打包、安装和设置保存。
3. 可见层只能通过已有事件桥接触发原始控件，不得移动、克隆或替换 React 管理的节点。
4. 参考设备为 `MZNRYXEQS859O7GU`，型号 `PEMM20`，Android 13；ADB 位于 `D:\文件翻译\.tools\platform-tools\adb.exe`。
5. 第一轮历史验收记录为 UI 契约 79/79、全量 237 passed、2 skipped；第二轮工作区修改尚未重新验证。
6. 历史 settings 帧样本为 17 帧、10 帧卡顿、50 分位 32ms，当前属于性能风险。

### 2.2 合理推测

- “感觉没有变化”主要来自旧业务骨架、大卡片和悬浮导航仍然存在，而不是单纯的 APK 安装错误。
- 第二轮优先调整首页密度、导航、品牌区和行级操作，比继续增加装饰动画更有效。

### 2.3 未验证项

- 60FPS、横屏、展开宽度、大字体、减少动画和深色模式的完整实测结果。

## 3. 目标与非目标

### 3.1 目标

- 建立统一的 Material 3 语义 token 和组件状态。
- 让首页、任务、安装包、设置、存档、弹层和错误页使用同一套视觉语言。
- 让每个任务状态都有主说明、下一步操作、恢复动作和可访问播报。
- 覆盖加载、空、错误、恢复、完成、删除中、删除失败和重试。
- 支持深色、系统字体放大、系统减少动画、Back、窄屏、横屏和展开宽度。
- 在真实 Android 设备上记录动画、滚动、进度和资源清理证据。

### 3.2 非目标

- 不迁移 Compose，不重写 React、Java、翻译引擎或数据结构。
- 不新增业务持久化字段、翻译供应商或后台任务。
- 不把 Remotion 作为 APK 运行时依赖。
- 没有 DSN、隐私策略和网络策略时不强行接入 Sentry。
- 不把未测量的 60FPS、横屏、平板或 clean-room build 写成完成。

## 4. 不可变业务合同

| 合同 | 约束 |
| --- | --- |
| 业务流程 | 选择来源 -> 扫描 -> 预检 -> 翻译 -> 打包 -> 安装/保存顺序不变 |
| React 控件 | 文件选择、开始翻译、安装、保存和设置保存继续触发现有 React 控件 |
| Java 桥接 | 方法名、参数字段、返回结构和异常语义不变 |
| 数据结构 | 任务快照、SourceSet、存档、安装包和设置字段不改名、不删除、不迁移 |
| 系统行为 | Back、文件选择器、安装确认和权限流程继续由现有业务或 Android 控制 |
| 文件安全 | 生成失败不删除已有生成文件；删除和清理保留现有确认和失败回退 |

允许新增的内容只包括 CSS class、可见层 DOM 区域、`aria-*` 标签、动画标记、测试夹具和 QA 证据，不得新增业务持久化字段。

## 5. 架构与状态模型

### 5.1 分层

```text
React/Java 业务层
  | 现有事件、现有字段、现有插件调用
  v
WebView 可见层
  | 稳定壳层、token、局部状态节点、动画和可访问性
  v
Android 系统层
  | Back、文件选择器、安装确认、状态栏和导航栏 inset
```

业务层负责事实和副作用；可见层负责表达；系统层负责系统页面和系统手势。可见层不得复制业务状态机。

### 5.2 稳定任务壳层

```text
workshop-task-shell
  ├─ workshop-task-topbar
  ├─ workshop-file-summary
  ├─ workshop-task-body
  │    ├─ workshop-state-region
  │    ├─ workshop-progress-region
  │    ├─ workshop-detail-region
  │    └─ workshop-action-region
  └─ workshop-live-status
```

规则：

1. 进度变化只更新当前文件、数字、宽度和最近状态。
2. 相同快照不重建壳层，不重播入场动画，不重复申请 Wake Lock。
3. 状态变化最多替换 `workshop-state-region`，其他区域保持节点身份。
4. 文件摘要、进度容器和列表行是共享元素连续性的语义锚点。
5. 日志默认不渲染，展开详情时按需生成。

### 5.3 八状态映射

| 状态 | 内容 | 主操作 | 恢复动作 | 导航 | 播报 |
| --- | --- | --- | --- | --- | --- |
| `idle` | 品牌说明、三步流程、文件空状态 | 选择应用或 APK | 打开安装包、我的 | 显示 | 静态页面不播报 |
| `scanning` | 文件摘要、阶段和线性进度 | 保留现有取消语义 | 返回并保留恢复信息 | 隐藏 | 阶段变化一次 |
| `empty` | 无可翻译内容的原因 | 重新选择 | 展开详情 | 隐藏 | 播报空结果 |
| `ready` | 数量、语言方向、兼容性和折叠文件列表 | 开始翻译 | 修复、切换或重新选择 | 隐藏 | 播报可开始或阻断 |
| `translating` | 当前文件、已完成数、总数、进度 | 保留现有暂停/恢复 | 保留现有重试/返回 | 隐藏 | 语义阶段一次 |
| `patching` | 正在生成可安装 APK、阶段和进度 | 保留现有生成行为 | 返回或重试 | 隐藏 | 播报生成阶段 |
| `completed` | 游戏名、完成数、文件名和大小 | 立即安装 | 保存 APK | 隐藏 | 播报完成结果 |
| `failed` | 原因、下一步、详情和恢复按钮 | 按错误类型恢复 | 重试、设置或重新选择 | 隐藏 | 播报错误和动作 |

## 6. 信息架构和页面合同

### 6.1 顶层导航

```text
首页
  ├─ 来源选择底部弹层
  │    ├─ 选择 APK 文件
  │    └─ 从已安装应用选择
  ├─ 安装包
  └─ 我的
       ├─ 翻译服务
       ├─ 存档转移
       ├─ 导入存档
       ├─ 清理安装包与旧缓存
       └─ 关于
```

### 6.2 首页 `idle`

- 顺序：应用名 -> 紧凑品牌说明 -> 三步流程 -> 文件摘要/空状态 -> 唯一主按钮 -> 导航。
- 品牌区不超过首屏可视高度的 22%，不使用点阵、光晕、持续渐变或默认毛玻璃。
- 三步流程在每格至少 96px 时使用三列，否则回退为可读的纵向列表。
- 主按钮高度 52 至 56px，只出现一次；导航栏安全区不得遮挡内容。
- 空状态文案：`尚未选择 APK`、`选择一个应用或 APK，开始你的中文旅程。`、`选择应用或 APK`。

### 6.3 来源选择和已安装应用

- 底部弹层顶部圆角 24px，遮罩只做透明度，不做实时模糊。
- 选项为选择 APK、已安装应用和取消；打开 220 至 260ms，关闭 180 至 220ms。
- 已安装应用必须显示应用名和包名；URI 只出现在详情。
- 覆盖加载、搜索、空结果、读取失败、重试和选择成功。
- 新行淡入并轻微上移；刷新失败保留旧列表和滚动位置。

### 6.4 扫描、空结果和准备就绪

- 扫描显示文件名、类型、阶段和线性进度，不伪造精确百分比，不显示大型旋转图标。
- 空结果说明检查范围、没有可处理内容的原因和重新选择动作；诊断码放入详情。
- 就绪页显示数量、语言方向和兼容性结果；文件列表默认折叠；阻断时主按钮改为修复或重新选择。

### 6.5 翻译、生成和完成

- 翻译中显示当前文件、数量、进度和最近状态；进度不重建整张任务卡。
- 生成中明确写出正在生成可安装 APK，保持主操作位置稳定。
- 完成页显示游戏名、完成数量、生成文件和大小；立即安装为主操作，保存 APK 为次操作。
- 安装失败不删除生成文件，返回结果页继续保存或重试。

### 6.6 错误恢复

错误类别包括：文件格式不支持、没有可翻译内容、网络或翻译服务失败、API Key 无效、空间不足、APK 生成失败、安装权限不足。

每个错误必须包含：发生了什么、下一步做什么、至少一个可执行动作和可展开原始详情。错误不能只靠颜色表达。

### 6.7 安装包、设置和存档

- 安装包字段：名称、大小、生成时间、保存/安装、删除。
- 列表状态：加载、空、正常、读取失败、删除中、删除成功、删除失败、重试。
- 删除只锁定当前行；成功后 180 至 240ms 淡出再移除；失败保留当前行。
- 设置首页分组：翻译服务、存档转移、导入存档、清理、关于。
- 存档备份、分享、导入、恢复和删除全部支持当前行 pending、成功、error 和 retry。
- 清理显示可释放空间和文件数量；破坏性操作先确认。
- 关于页只展示版本、支持和必要许可，不展示构建日志。

## 8. 动画合同

### 8.1 时长和属性

| 场景 | 时长 | 允许属性 |
| --- | --- | --- |
| 按钮按下 | 100 至 120ms | `transform`、颜色 |
| 状态切换 | 160 至 200ms | `opacity`、小幅 `transform` |
| 列表新增/删除 | 180 至 240ms | `opacity`、`transform` |
| 弹层 | 220 至 260ms | `opacity`、`transform` |
| 进度 | 200 至 260ms | 宽度、数字文本 |
| 普通交互上限 | 400ms | 超过则即时响应或分段表达 |

默认缓动为 `cubic-bezier(.33,1,.68,1)`。不动画大面积阴影、模糊、滤镜和复杂布局高度，不使用无限背景动画。

### 8.2 覆盖矩阵

| 路径 | 动画 | 约束 |
| --- | --- | --- |
| `idle -> scanning` | 文件摘要淡入、状态区轻微上移 | 只播放一次 |
| `scanning -> empty` | 状态区 fade-through | 主操作位置稳定 |
| `scanning -> ready` | 摘要和详情淡入 | 不重建壳层 |
| `ready -> translating` | 进度区原位展开 | 不重播卡片入场 |
| `translating -> patching` | 阶段标签切换 | 只更新变化节点 |
| `patching -> completed` | 进度淡出、完成摘要淡入 | 数字短暂过渡 |
| 任意状态 -> `failed` | 错误区淡入 | 按钮不跳动 |
| 来源选择 | 遮罩淡入、面板上移 | Back 反向关闭 |
| 列表新增 | 行淡入并上移 | 不刷新整页 |
| 行删除 | 当前行 busy，成功后淡出 | 失败保留并重试 |

### 8.3 共享元素和减少动画

- 文件图标、文件名、进度容器和列表行使用稳定语义锚点，不克隆或移动 React 节点。
- 导航 indicator 使用 `transform` 移动，不复制按钮。
- `prefers-reduced-motion: reduce` 时取消位移、缩放、shimmer、计数和离场动画，进度直接更新。
- 减少动画不改变状态、焦点、播报和操作路径。

## 9. 性能与兼容性

### 9.1 更新模型

1. 全局只保留一个 `MutationObserver`。
2. Observer 使用防抖和一个 `requestAnimationFrame` 合并刷新。
3. `shellKey` 只包含状态、文件身份、数量、错误原因和拆分信息。
4. `progressKey` 只包含当前文件、总数、已完成数量和阶段。
5. `progressKey` 变化不能触发任务壳层整块 `replaceChildren`。
6. 离开状态时释放 timer、observer、Wake Lock、focus 和 modal listener。

### 9.2 性能预算

| 指标 | 门槛 |
| --- | --- |
| 关键动画 | 按 16.7ms 帧预算观察 |
| 卡顿 | 三次重复采样不得相对基线明显回归；目标 janky frames 小于 10% |
| 高风险路径 | 若超过 20% 或明显高于基线，发布阻断并记录原因 |
| 长列表 | 单行操作，不得全列表重建 |
| 动画资源 | 无限 shimmer 默认关闭，无大面积持续动画 |
| 生命周期 | 不得残留 timer、listener、observer 或 Wake Lock |

当前 settings 历史样本为 58.82% janky，必须重新测量，不能视为通过。

### 9.3 兼容性

- 不提高现有 minSdk/targetSdk。
- `oklch`、`color-mix`、`:has` 不可用时仍可读、可点、可返回。
- 正确处理状态栏、导航栏、显示切口、软键盘和安全区 inset。
- 支持系统字体放大、深色模式、系统 Back 和横屏。
- 性能降级顺序：移除持续动画 -> 移除阴影动画 -> 减少层级 -> 即时切换。

## 10. 工具边界

### 10.1 Remotion

Remotion 只用于动效分镜、演示视频和 QA 资产，不进入 APK，不作为 WebView 运行时动画引擎。

### 10.2 Sentry

只有在 DSN、隐私策略和网络策略齐备后才可选接入。允许记录页面名、UI 状态、动画阶段、异常类型和版本指纹；禁止记录 API Key、文件内容、完整路径、存档内容和翻译文本。没有 DSN 时保持关闭。

### 10.3 oh-my-codex

只用于计划、审查和覆盖审计，不是 APK 运行时依赖。派生审查子任务时模型上限为 `5.6luna`，结果必须回到本文状态矩阵和验收门槛。

## 12. 测试和验收

### 12.1 契约测试

- 八个状态均有状态 class、主/恢复动作和 `aria-live`。
- `shellKey` 与 `progressKey` 分离；重复 snapshot 不渲染、不重播、不重复申请 Wake Lock。
- 减少动画关闭持续动画、位移和数字计数。
