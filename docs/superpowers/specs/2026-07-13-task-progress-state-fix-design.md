# 任务进度状态显示修复

## 目标

修复 APK 目录已经读取完成、翻译已经开始后，任务壳仍显示“正在读取 APK 目录”并持续累计扫描时间的问题。

## 根因

可见任务壳只定义了 `idle`、`scanning`、`ready` 和 `failed`。运行时检测到“正在处理脚本”“翻译中”或“开始处理”时，错误地返回 `scanning`，而 `scanning` 唯一对应的界面文案是“正在读取 APK 目录”。扫描和翻译因此共用了状态、文案和计时器。

## 状态设计

- `scanning`：只用于读取 APK 目录；显示扫描计时。
- `ready`：目录读取完成，显示文件数和“开始翻译”。
- `translating`：正在翻译脚本；显示文件级进度，不再运行扫描计时。
- `patching`：正在把译文写入补丁 APK；显示不可重复提交的处理中状态。
- `completed`：补丁 APK 已生成；提供“安装补丁版”。
- `failed`：保留现有扫描失败和空间不足恢复路径。

状态判定优先级为：失败 → 完成 → 写入补丁 → 翻译 → 就绪 → 扫描 → 空闲，避免旧日志中的“开始处理”覆盖后续阶段。

## 交互与文案

用户只看到当前真实阶段：扫描时说明“正在读取 APK 目录”，翻译时说明“正在翻译文本”，写入时说明“正在生成补丁 APK”。长耗时阶段保留“处理详情”，但技术日志不作为主文案。

翻译阶段必须同步现有 React 日志，而不是显示固定占位文案：卡片直接显示最新一条进度；“处理详情”显示最近 40 条日志。用户展开详情后，后续日志刷新不得折叠面板，并自动滚动到最新一条。

## 验收标准

1. 目录扫描返回后，扫描计时立即停止。
2. 点击开始翻译后，任务壳显示 `translating`，不再显示“读取 APK 目录”。
3. 生成补丁期间显示 `patching`；完成后显示 `completed` 和安装操作。
4. React 文本节点原地更新时，任务壳也能刷新状态。
5. 原有 API Key、文件选择、扫描、翻译和安装事件桥接保持不变。
6. 翻译日志新增后，最新一条在卡片内可见，最近 40 条可在“处理详情”查看。
