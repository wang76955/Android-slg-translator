# 已安装应用选择设计

## 目标

让用户既能选择手机中的 APK 文件，也能直接从已安装应用列表选择游戏。选择已安装应用后，翻译器应把该应用的基础 APK 安全复制到自身私有缓存，并复用现有扫描、文本提取、翻译和补丁生成流程。

## 用户流程

1. 首页主操作改为“选择应用或 APK”。
2. 点击后显示两个入口：
   - 从已安装应用选择
   - 从文件选择 APK
3. 已安装应用页提供搜索框，列表项显示应用名称与包名。
4. 列表只包含具有启动入口的普通应用，排除当前翻译器；不申请 `QUERY_ALL_PACKAGES`。
5. 选择应用后显示“正在读取应用安装包”，随后进入现有扫描和翻译流程。
6. 文件选择入口继续调用原有 `pickApkFile()`，行为保持不变。

## 架构

### 原生层

扩展现有 `FileManager` Capacitor 插件，新增两个方法：

- `listInstalledApps()`：通过 `ACTION_MAIN` + `CATEGORY_LAUNCHER` 查询用户可启动应用，返回按显示名称排序的 `{ label, packageName }`。不返回安装路径，不读取应用数据。
- `selectInstalledApp({ packageName })`：重新验证包名属于可查询的启动应用，读取 `ApplicationInfo.sourceDir`，将基础 APK 流式复制到翻译器私有缓存，返回与 `pickApkFile()` 兼容的 `{ uri, name, packageName, source: "installed" }`。

实现继续采用当前 `classes6.dex` 委托到 `classes7.dex` helper 的构建方式，避免重写整个原生插件。复制使用固定大小缓冲区、临时文件和原子重命名；失败或取消时清理临时文件。

### WebView 层

在现有可见工作台 shell 中增加来源选择底部面板和已安装应用列表。列表通过原生桥接加载，搜索仅在内存中按应用名称和包名过滤。选中后把原生返回的 URI 交给现有 React 文件选择后的扫描状态，不复制扫描与翻译逻辑。

为避免依赖文件选择按钮的闭包状态，补丁会增加一个明确的“应用来源选择结果”桥接入口，并用 DOM 事件/现有状态函数更新选择结果。若底层 React 无法接收外部 URI，则在构建时对原始选择函数抽取一个共享 `loadSelectedApk(selection)` 路径，让文件选择和已安装应用选择调用同一入口。

## Split APK 处理

选择时检查 `ApplicationInfo.splitSourceDirs`：

- 没有 split：正常继续。
- 存在 split：仍扫描基础 APK，但在进入扫描前显示明确提示“该应用使用拆分安装包，部分资源可能位于拆分包中”。
- 如果基础 APK 中没有可翻译文件，则停止并提示用户改用“从文件选择 APK”，不把零结果误报为应用没有文本。

首版不合并或重签多个 split APK，因为这会改变现有单 APK 补丁生成模型并显著增加安装失败风险。

## 安全与隐私

- 不新增 `QUERY_ALL_PACKAGES`。
- 不读取其他应用的私有数据，只读取系统公开的 APK 安装路径。
- 不输出 API Key、缓存译文、APK 内文本样本或真实安装路径到诊断日志。
- 缓存副本只保存在翻译器私有缓存目录；新选择覆盖旧选择时删除旧副本。
- 包名必须来自本次原生查询结果，拒绝任意路径或未经验证的包名输入。

## 错误处理

- 应用列表为空：提示“没有找到可选择的已安装应用”，保留文件选择入口。
- 应用在选择后被卸载或更新：提示重新选择，不复用失效路径。
- 存储空间不足：清理本次临时副本并显示可操作错误。
- 复制被中断：不进入扫描，不留下半成品 APK。
- Split APK 无可翻译文件：显示拆分包限制说明，不显示普通“无文本”完成态。

## 测试与验收

### 自动化测试

- 原生 helper 只查询 launcher 应用、排除自身、去重并排序。
- `selectInstalledApp` 验证包名、流式复制、临时文件清理和 split 标记。
- WebView 来源选择器同时保留“已安装应用”和“文件 APK”入口。
- 搜索按名称/包名过滤；空状态和错误状态可恢复。
- 两种来源最终调用相同扫描入口。
- 原有扫描、缓存、网络 fail-fast、安装按钮和 17 项回归测试继续通过。

### 真机验收

- 从已安装应用列表选择一个普通应用后能显示正确名称和包名并开始扫描。
- 原文件选择仍可用。
- 不授予 `QUERY_ALL_PACKAGES`，应用列表仍能展示 launcher 应用。
- 覆盖安装新版翻译器不降低现有 13,058 条缓存记录数。
- Split APK 会显示限制提示，不静默给出错误结论。
- 新 APK 通过 zipalign、v2/v3 签名验证，`adb install -r` 成功，启动日志无致命异常。

## 非目标

- 浏览系统服务、无启动入口组件或其他用户资料中的应用。
- 读取已安装应用的私有文件、存档或运行时内存。
- 合并、重签或安装完整的 split APK 集合。
- 在本功能中修改文本提取算法；“抓取文本不正确”将作为后续独立调试任务，用可复现样本单独修复。
