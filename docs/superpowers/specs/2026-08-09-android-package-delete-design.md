# Android 安装包删除与标题统一设计

日期：2026-08-09

## 背景

安装包页面当前通过 `FileManager.listPatchedApks()` 展示应用生成的补丁 APK。每个条目只有“保存到下载”操作，页面标题仍显示“我的补丁”。用户需要对每个安装包独立删除，并将标题统一为“安装包”。

## 目标

- 每个安装包条目提供独立的删除按钮。
- 删除前明确提示将删除的应用生成补丁 APK。
- 删除成功后列表立即反映结果，失败时显示可重试错误。
- 删除动作不卸载手机中的游戏，不删除用户原始 APK。
- 仅删除应用自己生成且能安全证明归属的 `*-patched-signed.apk`。
- 页面可见标题和无障碍标签统一使用“安装包”。

## 方案

采用原生精确删除接口配合前端确认交互：

1. `InstallSupport` 增加 `deletePatchedApk`。
2. 原生接口只接受列表返回的真实路径，校验目标是普通文件、文件名以 `-patched-signed.apk` 结尾，并且位于应用管理的输出目录内。
3. 删除接口不使用 `resolvePatchFile` 的“找最新文件”兜底，避免过期路径误删其他补丁。
4. 前端在每个条目右侧加入垃圾桶图标按钮，设置 `aria-label` 和 `title` 为“删除安装包”。点击后显示确认框，确认文案说明不会卸载游戏或删除原始 APK。
5. 删除成功后重新读取补丁列表；失败时保留条目并显示错误信息。
6. 右上角页面标题、页面 `aria-label` 和相关空状态文案从“我的补丁”改为“安装包”。

## 缓存边界

当前翻译缓存是跨任务共享的，没有按安装包建立独立索引。删除按钮只清理对应的应用生成补丁 APK，不删除无法证明属于该安装包的共享翻译缓存，以免破坏翻译续作和历史记录。

## 失败处理

- 路径为空、文件不存在、路径不在应用输出目录、文件名后缀不匹配时，原生接口拒绝删除并返回明确错误。
- 删除过程中列表保持可用，按钮进入禁用状态，防止重复请求。
- 原生删除成功但刷新失败时，显示刷新错误；下次进入页面仍可重新读取真实文件状态。

## 验证

- Python 合约测试验证标题、删除按钮、确认流程、成功刷新和失败保留条目。
- Java 编译与原生接口测试验证路径边界和拒绝危险路径。
- 构建 APK、签名、安装到真实设备。
- 在设备上验证：多个安装包各自删除、取消删除不改变列表、删除后 APK 不再出现在列表、原始 APK 和已安装游戏仍存在。
