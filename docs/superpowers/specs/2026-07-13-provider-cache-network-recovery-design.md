# 供应商、缓存与网络恢复设计

## 背景与证据

当前翻译任务在首个文件内长时间没有推进。真机 WebView 网络事件显示，对 `https://api.openai.com/v1/chat/completions` 的请求以 `net::ERR_CONNECTION_TIMED_OUT` 失败。翻译引擎同时启用了 SDK 内部重试和失败批次递归拆分，网络故障因此被放大为大量重复请求，界面一直停留在第一条。

手机中的翻译缓存没有丢失。原生缓存文件约 6.3 MB，共 13,058 条记录，其中 13,030 条属于 `en -> zh / deepseek-v4-flash`，当前界面却恢复为 `OpenAI / gpt-4o-mini`。旧缓存键包含模型名，导致同一源文本在切换供应商或模型后无法命中。

当前“我的”页面只暴露 API Key，没有供应商、模型和自定义接口设置。底层 React 页面已有 OpenAI、DeepSeek、自定义接口及模型控件，因此新界面应桥接这些现有控件，而不是建立第二套翻译配置。

## 目标

1. 在“我的”中完整配置 OpenAI、DeepSeek 和 OpenAI 兼容的自定义接口。
2. 供应商、模型和自定义接口地址在应用重启后保持不变。
3. 已有翻译缓存跨供应商、跨模型复用，同时保留源语言、目标语言和术语表隔离。
4. 网络不可达时快速停止，给出可操作提示，不再递归拆分和持续重试。
5. 保持现有文件选择、API Key、翻译、补丁生成和实时日志桥接行为。

## 非目标

- 不重写整个 React 应用或原生翻译引擎。
- 不删除、覆盖或批量重译现有缓存。
- 不把 API Key 上传到任何额外服务。
- 不增加供应商账号、余额或模型列表的远程探测。

## 设置界面

“我的”页面保留顶部返回栏，主体使用一个 Material 风格的“翻译服务”设置区，字段按依赖顺序排列：

1. **供应商**：OpenAI、DeepSeek、自定义接口。
2. **模型**：OpenAI 和 DeepSeek 使用各自现有模型列表。
3. **自定义 Base URL**：仅选择自定义接口时显示，示例为 `https://your-api.com/v1`。
4. **自定义模型名**：仅选择自定义接口时显示，接受 OpenAI 兼容接口使用的实际模型 ID。
5. **API Key**：沿用密码输入框，不在界面明文展示。
6. **保存设置**：统一保存并同步到底层 React 控件。

所有输入控件最小高度为 48 dp，沿用现有颜色、圆角、字体和焦点样式。保存成功后在按钮下方显示“已保存：DeepSeek · deepseek-v4-flash”等明确状态；自定义接口缺少 Base URL 或模型名时，使用字段下方错误文案并阻止保存。

## 配置桥接与持久化

可见设置页通过控件选项特征识别底层 React 表单，而不依赖压缩构建产生的变量名：

- 供应商控件包含 `openai`、`deepseek`、`custom`。
- 模型控件包含当前供应商模型选项。
- 自定义 Base URL 通过 `https://your-api.com/v1` 占位符识别。
- API Key 沿用现有密码输入框识别逻辑。

保存顺序固定为供应商、模型或自定义模型、Base URL、API Key。每个值都通过原生 `value` setter 以及冒泡的 `input`、`change` 事件同步 React 状态。自定义模型会先作为选项加入隐藏模型控件，再触发更新，使翻译请求获得真实模型 ID，而不是固定字符串 `custom`。

供应商、模型、自定义 Base URL 和自定义模型名保存到本机 `localStorage` 的单一 JSON 配置项。运行时挂载后自动恢复并同步到底层表单。API Key 继续沿用现有本机处理方式，不写入新的配置 JSON。

## 缓存兼容

新文本缓存键不再包含供应商或模型，只包含：

- 缓存版本；
- 源语言；
- 目标语言；
- 术语表哈希；
- 原文哈希。

加载缓存时建立一次内存索引，把旧格式

```text
slg-translator-cache:<source>|<target>|<model>|<glossaryHash>|<textHash>
```

映射到不含模型的稳定身份。若多个旧模型存在同一文本，选择 `updatedAt` 最新且内容完整的记录。命中旧记录后正常使用，并在后续保存时写入新格式，实现渐进迁移；原缓存文件不被清空。

完整文件输出缓存继续保持现状。即使文件级缓存因模型不同没有命中，文本级缓存也能恢复已有译文并快速重新生成该文件输出。

## 网络失败策略

OpenAI SDK 的内部重试从两次降为一次。批次失败处理区分两类错误：

- **网络错误**：连接超时、DNS、离线、连接被拒绝、`fetch` 失败。此类错误不得递归拆分批次；停止领取新批次，等待已经在途的请求结束后返回可操作错误。
- **内容错误**：模型返回空内容、JSON 解析失败、返回数量不匹配。此类错误仍允许递归拆分，以较小批次恢复可翻译内容。

网络错误文案根据 Base URL 显示供应商，例如：“无法连接 OpenAI。请检查网络，或前往‘我的’切换 DeepSeek。”错误必须进入现有日志并结束“翻译中”状态，不能无限保持禁用按钮。

## 数据流

```text
我的/保存设置
  -> 本机配置 JSON
  -> 同步隐藏 React 控件
  -> 翻译任务读取供应商、Base URL、模型和 API Key
  -> 先查询跨模型文本缓存
     -> 命中：直接生成译文输出
     -> 未命中：请求供应商 API
        -> 成功：写入新缓存键
        -> 内容错误：有限拆批
        -> 网络错误：停止新批次并显示恢复提示
```

## 测试与验收

### 自动化测试

1. 设置页包含供应商、模型、自定义 Base URL、自定义模型和 API Key 控件。
2. 保存时按依赖顺序同步 React 控件，并持久化非敏感供应商配置。
3. 重启挂载时恢复供应商和模型。
4. 新缓存键不包含模型；旧 DeepSeek 缓存可被 OpenAI 或 DeepSeek 当前配置命中。
5. 同一文本存在多条旧缓存时选择最新记录。
6. 网络错误不进入递归拆批，且停止领取新批次。
7. JSON 内容错误仍可拆批恢复。
8. 原有 APK 扫描、API Key、实时日志和补丁生成契约测试继续通过。

### 真机验收

1. “我的”可以切换 OpenAI、DeepSeek、自定义接口；自定义字段按条件显示。
2. 保存 DeepSeek 后关闭并重开应用，仍显示 DeepSeek 及所选模型。
3. 使用当前 APK 和 DeepSeek 时，日志显示现有缓存命中，不再显示缓存 0 条。
4. 使用不可达的 OpenAI 网络时，任务在有限重试后结束并显示切换供应商提示，不再卡住十分钟以上。
5. 可达供应商请求成功后，翻译进度和实时日志继续更新，并正常生成补丁 APK。

## 发布与数据安全

构建继续沿用现有 APK 补丁、zipalign 和 v2/v3 签名流程，并使用 `adb install -r` 覆盖安装，保留手机应用数据。安装前后分别统计缓存条数，确认 13,058 条旧记录未被清除。真机调试和测试输出不得打印 API Key 或完整缓存文本。
