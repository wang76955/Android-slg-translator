# APK 主流程 UI 重设计 v2：单屏状态向导

## 1. 目标

将当前“旧表单 + 新 Hero”叠加式界面，重构为面向普通 Android 玩家的单屏状态向导。主任务只围绕一个问题展开：用户是否已经准备好开始翻译？

核心路径：

`首页 → 选择 APK → 扫描 → 确认 → 开始翻译`

本次范围只覆盖主流程的四个状态，不扩展作品页和我的页的完整功能。

## 2. 设计原则

- 一屏只突出一个主决定；
- 状态变化原地发生，避免用户在页面间迷路；
- 技术细节默认收起，普通语言解释当前发生了什么；
- Android 任务页使用 Material 3 组件和系统 Back，不显示顶层底部导航；
- 失败状态必须给出原因和可执行的下一步；
- 保留现有 APK 选择、扫描、翻译和打包能力，不改变业务接口。

## 3. 页面状态模型

### 3.1 `idle`：首页

布局从上到下：

1. 顶部应用栏：标题“玩家工坊”，右侧保留主题入口；
2. 品牌介绍区：一句短文案“让喜欢的故事，用中文继续。”，使用橄榄绿作为品牌色块，但缩小高度，避免成为整屏海报；
3. 主操作卡：文件图标、标题“选择游戏 APK”、说明“从手机中选择要汉化的游戏文件”，唯一主按钮“选择 APK 文件”；
4. 最近任务空状态：没有历史时显示“选择一个 APK，开始你的第一次汉化”。

首页不展示 API Key、模型、任务模式、详细日志等高级内容。

### 3.2 `selected/scanning`：已选择与扫描中

选择文件后，主操作卡替换为文件摘要卡：

- 游戏图标或通用 APK 图标；
- 文件名，必要时截断并支持完整名称辅助说明；
- 文件大小；
- 状态标签“正在检查文件”；
- 线性进度指示器；
- 普通语言状态文案，例如“正在查找剧情文本，通常需要几秒钟”。

扫描中只保留“重新选择”作为次要文本按钮，不显示开始翻译按钮。技术日志放入“处理详情”折叠区域，默认关闭。

### 3.3 `ready`：扫描完成确认

扫描完成后展示确认卡：

- 成功状态图标与“可以开始了”；
- “发现 X 个可翻译文件”；
- 源语言 → 目标语言；
- 输出位置和预计空间（若可取得）；
- 可展开“处理详情”查看文件类型、路径和诊断日志；
- 底部固定一个 Material Filled Button：“开始翻译”。按钮宽度随内容收敛，不铺满屏幕。

高级设置（API Key、模型、任务模式）放到确认卡后的“翻译设置”折叠区；只有开始前需要修改时才展开。

### 3.4 `failed`：可恢复失败

错误卡必须包含：

- 普通语言标题，例如“手机空间不足”；
- 简短说明，例如“生成补丁 APK 需要临时空间，当前空间不够”；
- 主操作“释放空间后重试”；
- 次操作“重新选择 APK”；
- 可复制的原始诊断信息只放在“处理详情”内。

对于 `ENOSPC`，禁止只显示“写入补丁 APK 失败”。

## 4. 导航与返回

- `idle` 状态显示 Material 3 Navigation Bar：首页、作品、我的；
- `selected/scanning/ready/failed` 状态隐藏底部导航，避免遮挡任务操作；
- Android 系统 Back：从任务状态返回首页并保留已选择文件；再次 Back 才退出页面；
- 不移动 React 管理的原始按钮节点，只通过稳定的事件桥接触发文件选择和开始翻译。

## 5. 视觉系统

- 页面背景使用纯白或极浅中性表面；
- 橄榄绿仅用于品牌区、主操作和成功状态，不将整个页面染成绿色；
- 黄色作为少量强调色，不作为所有主按钮背景；
- 卡片使用 16–20dp 圆角、轻描边、无厚重阴影；
- 按钮遵循 Material 3：Filled Button 用于唯一主操作，Tonal/Outlined Button 用于次要操作，触控高度不少于 48dp；
- 使用系统无衬线字体，标题、正文、标签采用紧凑的 Material type scale；
- 尊重深色模式、系统字体缩放和“移除动画”。

## 6. 交互与状态边界

- 文件选择取消：回到 `idle`，不显示错误；
- 非 APK 或无可处理文本：停留在文件摘要卡，说明支持范围并提供“重新选择”；
- 空间不足：进入 `failed`，保留已生成文件和任务信息，不自动删除可重试产物；
- 翻译开始后：主按钮变为进度状态，避免重复提交；
- 日志只作为诊断信息，不作为主流程导航；
- 所有状态转换使用 150–250ms fade-through，减少动画设置时即时切换。

## 7. 验收标准

1. 新用户不需要看到 API Key、模型或日志，就能完成 APK 选择和扫描确认；
2. 选择、扫描、确认、失败四种状态的主操作互不冲突；
3. 任务状态页不出现底部导航遮挡；
4. 扫描完成后，用户能在一屏内看到文件数、语言方向、输出位置和“开始翻译”；
5. `ENOSPC` 等错误显示可理解原因和下一步；
6. 48dp 触控目标、深色模式、字体缩放和系统 Back 均通过真机回归；
7. 现有文件选择、翻译、打包和安装接口行为保持不变。

## 8. 实施边界

本规格批准后，下一步只实现主流程 UI 壳和状态映射；作品页、我的页的完整内容、API Key 加密存储和打包架构优化另行处理。
