# Android 官方增强版升级设计

## 1. 文档目的

本文档定义 SLG Translator Android 官方增强版在免费外部测试期结束后的功能升级路线、产品边界、数据模型、实施顺序和验收门禁。

本文档回答“增强版逐步实现什么、先后顺序是什么、每项能力如何证明完成”。收费方式、权益核销、维护期、支付验证和最小后端边界继续以 2026-08-07-android-enhanced-monetization-design.md 为准；Ren'Py 格式兼容、发布矩阵和底层验证继续以 2026-08-07-renpy-app-compatibility-optimization.md 及后续重验文档为准。

增强版的主价值定义为：

> 在不隐藏开源核心能力、不重复收取模型费用的前提下，用持续更新的兼容规则、自动检查、故障恢复、增量复用和官方支持，提高普通玩家一次完成 Ren'Py Android 游戏汉化的概率。

“汉化成功保障”是产品功能包名称，不代表对所有游戏作出 100% 成功承诺。产品必须在购买前说明支持等级和残余风险；无法安全处理时免费阻止；任务失败时释放项目权益；只有通过规定验证的产物才允许显示为完成。

## 2. 启动增强版实施的前置条件

增强版功能可以在测试期内进行设计和内部验证，但面向用户启用付费权益前，至少满足以下条件：

1. 至少 30 名真实用户完成 APK 扫描；
2. 至少 10 名用户使用合法测试游戏成功生成、安装并运行汉化 APK；
3. 扫描、提取、翻译、编译、签名、安装和启动失败已经结构化分类；
4. 已确认排名最高的失败类型及其修复优先级；
5. 长任务能够保存检查点，应用重启后不会丢失有效翻译；
6. 兼容性报告不会把未知或不安全格式误报为可完整处理；
7. 发布分支的强制自动化测试通过，真机强制项具备当前证据；
8. 开源核心版和官方增强版的能力边界已在应用、官网和 README 中保持一致；
9. 已建立统一反馈入口、脱敏诊断流程和项目支持记录；
10. 用户在启动增强流程前能看到 AI 费用不包含在增强版价格中的明确说明。

未满足这些条件时，可以继续提高产品成功率，但不应通过提前建设复杂支付系统来掩盖产品缺口。

## 3. 产品原则

### 3.1 成功率优先

增强版的优化顺序固定为：

1. 游戏实际运行成功率；
2. 译文覆盖完整性和安全性；
3. 任务恢复能力；
4. 游戏更新后的结果复用；
5. 普通用户操作成本；
6. 翻译风格和高级编辑能力；
7. 支付转化和收入扩展。

### 3.2 不制造伪成功

以下状态必须严格区分：

- 已完成扫描；
- 已完成文本提取；
- 已完成 AI 翻译；
- 已通过文本质量检查；
- 已通过覆盖率和字体检查；
- 已生成并验证翻译产物；
- 已生成 APK；
- 已完成 APK 对齐和签名验证；
- 已安装；
- 已启动游戏；
- 已在游戏内确认中文生效。

仅生成文件或完成安装不能显示为“汉化成功”。面向用户的完成状态至少要求翻译产物、APK 完整性、zipalign 和签名验证通过；真实运行成功率必须以启动和中文生效证据计算。

### 3.3 核心开源，增强服务收费

开源核心版继续保留标准 Ren'Py APK 的基础扫描、提取、翻译、重打包和原始日志能力。增强版出售的是持续维护和自动化价值：

- 自动更新的兼容规则；
- 更完整的格式识别和安全回退；
- 面向普通用户的兼容性解释；
- 自动质量门禁与可修复建议；
- 完整检查点和任务恢复；
- 项目级翻译记忆和增量更新；
- 字体、语言入口、签名和安装保障；
- 维护期内的诊断和优先支持。

不得把已经公开的核心能力重新加锁，也不得故意削弱开源版制造付费动机。

### 3.4 本地优先与最小数据

默认在设备本地处理和保存：

- 游戏 APK 和拆分 APK；
- 游戏剧情正文；
- 完整翻译结果；
- 用户 API Key；
- 字体和翻译补丁；
- 项目翻译记忆。

服务端只保存账号、订单、权益、项目受控标识、维护期、授权、阶段结果和最小兼容性统计。API Key、完整 APK、完整剧情和完整译文不得作为商业分析数据上传。

### 3.5 确定性校验优先

标签、变量、占位符、转义、文件边界、字体字符覆盖、RPYC 结构、APK 对齐和签名必须由确定性程序检查。提示词只能降低错误概率，不能代替质量门禁。

## 4. 增强版功能包

### 4.1 兼容性护照

#### 用户价值

用户在购买或消耗权益前，知道当前游戏能否处理、预计能够翻译多少、存在什么风险以及最终使用哪种中文激活方式。

#### 功能要求

兼容性护照至少包含：

- 游戏名称、图标、包名受控展示和项目身份；
- 单 APK 或 base + split 结构；
- Ren'Py 版本或可解释版本区间；
- RPA、RPYC、RPYMC 和资源布局识别结果；
- 文本出现次数、唯一文本数和可确定覆盖数；
- 剧情、菜单、界面、角色名、公共文本和不确定文本分类；
- RPYC 读取和写入能力；
- 字体候选、中文字符覆盖和东亚断行证据；
- 可切换语言、默认中文或无法安全激活；
- APK 重打包、对齐、签名和安装形态风险；
- SAFE、WARNING、EXTRACT_ONLY、UNSUPPORTED 支持等级；
- 预计翻译条目、处理时间和用户自付模型成本区间；
- 阻断项、警告项、建议操作和残余风险。

#### 行为边界

- 扫描和兼容性护照免费；
- UNSUPPORTED 不允许消耗权益；
- EXTRACT_ONLY 只允许导出文本和诊断；
- WARNING 必须要求用户明确确认风险；
- 护照绑定 APK 集合哈希和规则版本，源文件变化后自动失效；
- 护照不得包含游戏剧情正文或敏感路径。

#### 完成证明

- 固定样本覆盖单 APK、Split APK、Ren'Py 7/8、不同 RPA/RPYC 和不支持格式；
- 护照 JSON 与用户界面一致；
- 不支持样本被正确阻止；
- 每个支持结论能追踪到机器证据或显式未知状态。

### 4.2 汉化成功保障流水线

#### 固定流程

~~~text
兼容性护照
→ 结构化文本提取
→ 翻译与缓存
→ 标签、变量和占位符检查
→ 覆盖率检查
→ 字体和断行检查
→ 翻译产物编译
→ RPYC/覆盖层独立验证
→ APK 合并
→ zipalign
→ V2/V3 签名验证
→ 安装前检查
→ 安装或保存
→ 启动与中文生效引导
~~~

#### 功能要求

- 每个阶段产生结构化结果、耗时、输入哈希和输出哈希；
- 任一阻断检查失败时禁止进入后续危险阶段；
- 同一任务只能使用与最近一次检查一致的源文件、译文和规则版本；
- 修复译文后只重跑受影响的检查；
- 对允许的不完整测试补丁持续显示明显警告；
- 只有通过基础校验的可安装 APK 产出后才能核销权益；
- 权益核销不等同于真实运行成功，后续运行结果单独记录；
- 所有失败映射为普通语言说明、建议动作和可复制诊断码。

#### 完成证明

- 任一检查失败均无法绕过构建门禁；
- 改变 APK、翻译或规则版本会使旧检查结果失效；
- 生成产物经过独立读取和校验；
- 固定样本完成扫描到签名的可重复验证；
- 真机完成安装、启动和中文生效验证。

### 4.3 任务保险与故障恢复

#### 功能要求

- 每个翻译批次成功后持久化检查点；
- 应用被系统回收或重启后恢复最近安全阶段；
- 暂停后不继续发送模型请求或修改产物；
- 断网、超时、限流和临时服务错误使用有上限的退避重试；
- API Key 失效时保留任务，更新密钥后继续；
- 打包、签名或安装失败不删除译文、翻译记忆和已验证中间产物；
- 检查点包含任务版本，旧版本不兼容时明确迁移或安全回退；
- 用户放弃任务前明确说明保留和删除哪些内容；
- 自动清理只处理已确认无引用的临时文件。

#### 任务状态

~~~text
SELECTED
SCANNING
READY
TRANSLATING
PAUSED
VALIDATING
PACKAGING
SIGNING
INSTALL_READY
COMPLETED
RECOVERABLE_FAILURE
BLOCKED
CANCELLED
~~~

#### 完成证明

- 翻译中强制结束应用后可继续；
- 网络恢复后不重复计入已成功批次；
- API Key 更换后从失败批次继续；
- 打包失败后修复条件并重试不重新翻译；
- 检查点损坏时隔离损坏数据并保留其他可恢复项目。

### 4.4 翻译质量守卫

#### 检查范围

- Ren'Py 标签及闭合关系；
- 插值变量和嵌套插值；
- printf 占位符；
- 转义字符、换行和不可见控制符；
- 菜单选项空值；
- 角色名和短标签误翻；
- 文件名、URL、代码片段和资源标识误翻；
- 源文与译文长度异常；
- 译文残留大量源语言；
- 相同原文在不同语境下的冲突；
- 中文标点、引号和空格基础规范；
- 译文编码和不支持字符。

#### 结果级别

- PASS：可以进入构建；
- AUTO_REPAIRED：确定性修复完成并重新校验；
- REVIEW_REQUIRED：语义或语境问题需要确认；
- BLOCKED：会破坏运行或显示，禁止构建。

允许自动修复可逆、确定的问题。不得在无法确定位置时猜测插入变量，不得自动改写游戏控制流，不得把删除标签作为修复策略。

#### 完成证明

- 每种标签、插值、printf、转义和异常类型有正反测试；
- 人工确认译文不会被 AI 或自动修复静默覆盖；
- 自动修复保存修改前后值、规则和时间；
- BLOCKED 条目无法进入完整构建。

### 4.5 项目级翻译记忆

每条记录至少包含：

~~~text
projectId
sourceContextId
sourceHash
sourceText
translatedText
targetLanguage
provider
modelId
ruleVersion
status
placeholderSignature
tagSignature
humanVerified
createdAt
updatedAt
~~~

sourceContextId 由源文件、文本类型、角色、稳定位置或可用的 Ren'Py 上下文组成，不能只按原文复用短句。

#### 功能要求

- 相同项目、相同语境和相同源文自动命中；
- 人工确认结果优先于 AI 建议；
- AI 不得静默覆盖 humanVerified 记录；
- 模型、规则或目标语言变化时建立新版本；
- 支持查看和恢复历史译文；
- 支持导出和导入项目翻译记忆；
- 存储采用追加记录或等价的可审计版本机制；
- 缓存命中仍须经过当前版本的确定性校验。

#### 完成证明

- 重复任务不重新调用已命中的条目；
- 不同游戏的相同短句不会错误串用；
- 人工确认译文在模型切换后保持不变；
- 旧记录能迁移、导出和恢复；
- 可计算缓存命中率和节省的模型调用。

### 4.6 游戏更新后的增量汉化

新旧版本至少分类为：

- 未变化且可安全复用；
- 文件位置变化但语境足够稳定；
- 新增文本；
- 原文发生变化；
- 已删除文本；
- 语境冲突，需要人工确认；
- 引擎、资源、字体或语言激活结构发生变化，需要重新预检。

项目身份综合使用包名、Ren'Py 元数据、资源结构和签名前关键内容特征，不能只使用 APK 哈希。大版本结构变化时可以识别为同一逻辑游戏，但必须重新执行完整兼容性护照和构建验证。

增量报告显示总文本、直接复用、新增、变更、冲突、删除和预计节省比例，并允许只处理新增内容或指定角色、文件和异常类型。

#### 完成证明

- 固定旧版和新版样本生成可重复 diff；
- 位置变化不会导致无条件复用；
- 结构变化会使相关旧检查失效；
- 增量结果使用与全量结果相同的质量和构建门禁。

### 4.7 术语、角色名和口吻一致性

#### 功能要求

- 从项目文本提取角色名和高频术语候选；
- 支持固定译法、不翻译词、角色称呼、身份和语气说明；
- 翻译请求附带与当前条目相关的最小术语上下文；
- 翻译后检查同一术语多译、角色名称变化和禁译词被翻译；
- 用户可以批量接受候选、修改规则和重检受影响条目；
- 术语表按项目隔离并纳入翻译记忆版本；
- 首版使用本地结构化规则和提示词注入，不依赖云端向量数据库。

#### 完成证明

- 固定长文本样本能识别术语不一致；
- 修改术语只使受影响条目进入重检；
- 术语建议和强制规则在界面中明确区分；
- 不向非用户选择的服务上传无关上下文。

### 4.8 智能字体与东亚排版保障

#### 功能要求

- 从最终译文计算所需 Unicode 字符集合；
- 检查游戏字体候选的字符覆盖；
- 区分普通、粗体、斜体和 fallback 风险；
- 检查中文样式和东亚换行证据；
- 显示缺字数量和代表性缺字；
- 自动选择明确允许嵌入和重新分发的字体候选；
- 预估字体注入后的 APK 体积和设备空间；
- 严重缺字时阻止正式构建；
- 支持代表性剧情、菜单和角色名预览；
- 保存字体来源、版本和许可证证据。

#### 完成证明

- 最终译文字符集合与字体报告一致；
- 缺字样本被阻止，完整字体样本通过；
- 注入字体在真机显示中文、标点和常用符号；
- 无明确许可证的字体不会自动进入发行产物。

### 4.9 语言入口自动适配

#### 功能要求

- 识别原游戏是否存在语言菜单；
- 判断 SELECTABLE_LANGUAGE、ALWAYS_ON 或 NONE；
- 可安全添加入口时生成简体中文选项；
- 无法安全添加入口时明确使用默认中文并告知不能切回原文；
- 检查语言选择持久化；
- 检查新游戏、旧存档、rollback 和跳转后的语言行为；
- 高风险 dialogue ID 模式默认关闭，仅在真实证据满足时启用；
- 未知版本不生成任意 Python 字节码或猜测游戏控制流。

#### 完成证明

- selectable 样本能切换到中文并切回原文；
- always-on 样本的完成页说明与实际一致；
- 自定义界面导致入口不可见时报告问题；
- 新游戏和旧存档均有真机证据。

### 4.10 一键打包、签名、安装和启动引导

#### 功能要求

- 统一生成翻译覆盖层并合并正确 APK 集合；
- base 和 split 使用一致签名并在单个安装 session 中处理；
- 执行 zipalign、V2/V3 签名和产物验证；
- 检查包名、版本号、ABI、SDK 和签名冲突；
- 安装权限缺失时进入系统授权，返回后恢复任务；
- 安装失败不删除生成文件；
- 支持保存 APK 到用户可找到的位置；
- 安装完成后提供启动游戏和中文验证引导；
- 保留原始 APK、项目配置和可恢复结果；
- 保存 APK 集合哈希、签名指纹和构建报告。

#### 完成证明

- 单 APK 和真实 Split APK 分别通过构建、签名和安装；
- 签名冲突、空间不足、权限缺失和版本降级有恢复路径；
- 安装失败后可以保存文件或重试；
- 完成状态与实际构建、签名、安装和启动结果一致。

### 4.11 安装前存档保护

#### 功能要求

- 检测原游戏是否已安装；
- 在签名变化或无法覆盖安装时显示风险；
- 在系统和权限允许时导出可访问存档；
- 存档备份绑定项目身份、包名、游戏版本和时间；
- 安装后提供恢复入口；
- 拒绝把明显属于其他项目的存档导入当前游戏；
- 无法访问受保护目录时明确说明限制；
- 不承诺绕过 Android 沙箱或所有游戏均可自动迁移；
- 存档操作失败不阻止用户保存生成的 APK。

#### 完成证明

- 可访问样本完成导出、安装和恢复；
- 不可访问样本显示准确限制；
- 项目身份不匹配时阻止误导入；
- 存档操作不静默删除原文件。

### 4.12 脱敏诊断包与项目维护

诊断包允许包含：

- 应用版本、Android 版本、设备架构；
- 项目匿名标识和 APK 集合哈希；
- Ren'Py、RPA、RPYC 和安装形态摘要；
- 每个阶段的状态、耗时和错误分类；
- 兼容性、覆盖率、质量、字体和签名报告；
- 任务恢复和重试摘要；
- 用户主动勾选的截图或补充信息。

默认排除：

- API Key；
- 完整 APK；
- 游戏剧情正文；
- 完整译文；
- 无关本地路径；
- 账号凭据和可复用授权秘密。

#### 功能要求

- 提交前允许查看诊断包清单和文本内容；
- 用户可以只导出到本地，不必上传；
- 诊断码关联项目维护期和支持记录；
- 维护期内支持修复、重检、重打包和符合条件的增量更新；
- 支持操作记录耗时、结果和是否属于产品兼容问题；
- 无法自动处理的特殊游戏优先返还权益或退款，不承诺无限人工定制。

#### 完成证明

- 自动测试证明敏感字段不会进入诊断包；
- 用户可以预览、取消、保存和提交；
- 支持人员能定位阶段、错误分类和规则版本；
- 支持成本能按项目统计。

## 7. 组件边界与数据流

增强版不复制独立 Ren'Py 引擎，而是在现有核心组件之上增加受控编排层。

~~~text
项目身份与权益
      ↓
兼容性护照编排器
      ↓
现有扫描、RPYC/RPA、字体和覆盖率组件
      ↓
翻译任务编排器 ──→ 翻译记忆与术语规则
      ↓
质量守卫
      ↓
编译、产物验证、APK 合并和签名
      ↓
安装、启动引导和存档保护
      ↓
本地证据、脱敏诊断和维护记录
~~~

建议组件职责：

1. ProjectIdentityService：识别同一逻辑游戏和版本关系；
2. CompatibilityPassportService：汇总预检结果并形成稳定报告；
3. EnhancedTaskOrchestrator：状态、检查点、暂停、恢复和核销触发；
4. TranslationMemoryStore：项目级版本化翻译记忆；
5. TerminologyService：术语、角色和语气规则；
6. QualityGateService：统一文本、覆盖率、字体和产物门禁；
7. IncrementalProjectService：新旧版本 diff 和结果复用；
8. DeliveryService：覆盖层、打包、签名、安装和证据；
9. SaveProtectionService：存档风险、导出和恢复；
10. DiagnosticBundleService：本地脱敏诊断包；
11. EntitlementAdapter：隔离人工授权和未来自动权益后端。

组件通过结构化接口通信，不能通过解析 UI 文案或压缩 JavaScript 内部位置推断状态。

## 8. 分阶段实施路线

### Phase E0：增强版基础收口

目标：把测试期已有底层能力整理为稳定基础，不启用自动收费。

范围：

- 冻结项目身份、任务、护照和证据 schema；
- 完成当前批次 B/C 重验和发布门禁；
- 将兼容性、覆盖率、字体和 RPYC 结果统一接入；
- 建立增强版功能开关和人工授权适配器；
- 建立脱敏错误分类和本地证据目录；
- 建立开源版/增强版能力契约测试。

退出门禁：

- 强制测试和真机门禁通过；
- 同一 APK 生成稳定一致的兼容性结论；
- 开源核心流程不因增强版接线退化；
- 增强版关闭时仍可完成承诺的基础流程。

### Phase E1：成功保障 MVP

目标：形成首个可感知、可人工授权测试的增强版功能包。

范围：

- 兼容性护照；
- 汉化成功保障流水线；
- 任务保险与恢复；
- 质量守卫的阻断级规则；
- 智能字体最终检查；
- 一键打包、签名、安装和保存；
- 本地脱敏诊断包。

退出门禁：

- UNSUPPORTED 和 EXTRACT_ONLY 不会误进入完整构建；
- 标签、插值、printf、覆盖率、字体和产物失败可阻断；
- 应用重启、断网和 API Key 失效后可恢复；
- 单 APK 与适用 Split APK 样本完成端到端验证；
- 人工授权和失败释放权益可演练；
- 用户能理解支持等级、风险和失败原因。

### Phase E2：翻译记忆与增量更新

目标：建立持续复购价值，并减少用户模型费用和等待时间。

范围：

- 项目级翻译记忆；
- 人工确认不可被 AI 覆盖；
- 历史译文和恢复；
- 游戏版本识别；
- 新旧版本增量 diff；
- 按新增、变化和冲突条目处理；
- 缓存命中和节省统计。

退出门禁：

- 同一项目小版本更新可稳定复用译文；
- 不同项目无错误串用；
- 结构变化触发相关门禁重验；
- 增量结果使用完整质量门禁；
- 可测量节省的调用数、时间和估算费用。

### Phase E3：长篇剧情质量增强

目标：提升角色、术语和口吻一致性。

范围：

- 角色和术语候选提取；
- 固定译法和不翻译词；
- 语气规则；
- 同词多译检查；
- 翻译前抽样预览；
- 按角色、文件或异常类型重新处理；
- 原文、当前译文和历史译文对比；
- 先实现一种稳定的 PO、JSON 或 CSV 交换格式。

退出门禁：

- 术语规则稳定影响相关条目；
- 修改规则不会无条件重译全项目；
- 人工确认和历史版本可恢复；
- 长文本一致性指标可计算并解释；
- 编辑和导入不能绕过质量门禁。

### Phase E4：交付和维护体验

目标：降低安装、存档和售后支持造成的失败与人工成本。

范围：

- 语言入口自动适配和明确回退；
- 安装前存档保护；
- 签名冲突和覆盖安装引导；
- 安装后启动和中文验证清单；
- 维护期项目中心；
- 诊断包提交和支持状态；
- 官方兼容规则的签名更新；
- 失败权益返还和维护期延长的人工管理操作。

退出门禁：

- 无需完整 APK 和剧情正文即可定位主要失败类型；
- 存档可访问和不可访问场景均有准确结果；
- 规则更新可验证来源、签名、版本和回滚；
- 单项目支持时间、退款原因和复购可统计；
- 不把特殊游戏演变成无限人工定制。

### Phase E5：商业闭环自动化

目标：在人工付费和复购得到验证后，自动化账号、订单、权益和授权。

前置商业信号：

- 至少 3 笔真实付款；
- 至少 5 名用户愿意以约 ¥9.9 购买第二个项目，最好存在实际复购；
- 购买原因主要是增强能力而非友情支持；
- 单项目平均支持成本可控；
- 退款和重大失败未暴露产品根本问题。

范围：

- 低摩擦身份；
- 单项目和三项目包；
- 订单、支付和退款；
- 权益锁定、核销、返还；
- 项目维护期；
- 短期签名授权；
- 设备恢复；
- 最小管理后台；
- 商业漏斗统计。

复杂积分、优惠券、分佣、代理、社交、排行榜、无限会员和云端托管游戏内容不进入本阶段。

## 9. 发布、灰度和回滚

每个阶段独立发布，不把多个高风险能力一次性全量开启。

功能开关至少按应用版本、Ren'Py 能力等级、单 APK/Split APK、激活策略、测试用户组和授权状态生效。客户端必须内置安全默认值；远程配置不可把 UNSUPPORTED 强制改为可写，也不可关闭签名、字体、占位符或产物验证门禁。

灰度顺序：

~~~text
开发者固定样本
→ 内部真实设备
→ 免费测试用户
→ 人工授权增强版用户
→ 小比例正式用户
→ 全量支持范围
~~~

每次扩大范围前检查运行成功率、退款率、恢复成功率、支持时长、诊断完整率和新增失败类型。

回滚要求：

- 规则库保留当前和上一稳定版本；
- 任务记录实际使用的规则和编译器版本；
- 发现严重误判时停止新任务，不破坏已有结果；
- 新功能关闭后仍允许导出已有翻译、诊断和 APK；
- 权益异常由服务端或人工适配器安全返还。

## 10. 测试和证据要求

增强版每项能力至少通过以下适用层级：

~~~text
L1  单元测试
L2  组件契约测试
L3  任务恢复和失败路径集成测试
L4  全量自动化回归
L5  Helper DEX 和 APK 构建验证
L6  RPYC、覆盖层、zipalign 和签名独立验证
L7  真实游戏静态审计
L8  真实 Android 设备端到端验证
L9  外部测试用户成功与支持记录
~~~

每项完成证据记录 requirementId、featureVersion、sourceHash、ruleVersion、automatedTest、command、status、artifact、deviceOrSample、residualRisk 和 commit。

缺少真实设备、Split APK、旧存档或语言切换样本时，对应能力保持 NOT-RUN，不得以 fixture 或 APK 成功生成替代真实运行证明。

## 11. 指标体系

### 11.1 成功率指标

- 免费扫描成功率；
- 各支持等级分布；
- 文本提取成功率；
- 翻译任务完成率；
- 质量门禁一次通过率和自动修复成功率；
- APK 打包、签名和安装成功率；
- 游戏启动和中文生效确认率；
- 旧存档和语言切换成功率。

### 11.2 增强价值指标

- 检查点恢复成功率；
- 翻译记忆命中率；
- 增量汉化复用率；
- 预计节省的模型调用和费用；
- 避免生成坏包的项目数量；
- 诊断包一次定位率；
- 单项目平均支持时长；
- 维护期内重打包和更新成功率。

### 11.3 商业指标

- 兼容性通过到查看增强版比例；
- 查看增强版到咨询或购买比例；
- 付款到产出成功率；
- 权益释放、返还和退款率；
- 30/60/90 天复购率；
- 单项目贡献收益；
- 用户实际购买原因。

下载量、注册量和扫描量不能替代运行成功率、复购和支持成本。

## 12. 安全、许可和合规边界

- APK、RPA、RPYC、pickle、字体和导入文件均视为不可信输入；
- 解析设置大小、数量、递归、解压和耗时限制；
- 不执行游戏代码，不使用无约束反序列化；
- 不自动修改 jump、call、条件分支和任意游戏逻辑；
- 不托管、分发或自动下载用户无权处理的游戏；
- 不把完整游戏或剧情上传作为默认诊断方式；
- 第三方解析器、字体和工具在使用前记录许可证、版本和来源；
- GPL、EUPL、source-available 和无许可证项目不能按 MIT 代码直接复制；
- 自动收款前根据经营主体、分发渠道和支付方案完成法律、隐私和支付资质核查；
- “仅供学习交流”不能替代用户对游戏文件的合法权利；
- 产品说明使用“提高成功率”“失败可恢复”和“通过检查后产出”，避免绝对成功承诺。

## 13. 不进入近期增强版的功能

- 云端托管完整 APK、完整剧情或完整译文；
- 自动下载游戏；
- 公共汉化资源市场；
- 社交、聊天、排行榜和动态；
- 积分、复杂优惠券、推广分佣和代理商体系；
- 无限项目会员和低价终身会员；
- 多人实时协作编辑；
- 重度 DRM 和不合理设备绑定；
- 为绕过限制自动修改任意游戏控制流；
- 首发同时扩展 RPG Maker、Unity、Godot 等多引擎；
- 用双模型或大型云端 RAG 替代基础确定性校验；
- 对不支持格式“尽量写入”并让用户承担坏包风险。

## 14. 实施优先级摘要

测试期结束后的固定顺序：

1. E0 基础收口：证明底层能力和发布门禁可靠；
2. E1 成功保障 MVP：兼容性护照、质量门禁、恢复、字体、打包安装和诊断；
3. E2 翻译记忆与增量更新：建立持续价值和复购理由；
4. E3 长篇剧情质量增强：术语、角色、语气、预览和审校；
5. E4 交付和维护体验：语言入口、存档、规则更新和支持闭环；
6. E5 商业自动化：真实付费和复购成立后再实现支付后端。

首发增强版的六个用户可理解卖点：

1. 兼容性护照；
2. 汉化成功保障流水线；
3. 任务保险；
4. 智能翻译记忆和增量更新；
5. 一键安装与存档保护；
6. 项目维护和脱敏诊断支持。

## 15. 设计完成定义

本升级设计完整实现的条件是：

- E0–E4 的强制门禁均有当前、可重复证据；
- 开源核心版仍能完成承诺的基础端到端流程；
- 增强版不会对无法安全处理的游戏收费；
- 阻断级质量问题无法绕过构建；
- 任务中断后可从最近安全阶段恢复；
- 人工确认译文不会被 AI 静默覆盖；
- 同一游戏更新能安全复用结果并重做必要检查；
- 单 APK、适用 Split APK、selectable 和 always-on 均有真实样本证据；
- 字体、语言激活、签名、安装、旧存档和启动不以文件存在性代替真机验证；
- 诊断包不包含 API Key、完整游戏正文和其他默认禁止数据；
- 支持成本、退款原因、成功率和复购能够度量；
- 商业自动化只在真实付费信号达到后启动。

## 16. 文档自检

- 范围一致：只定义测试期后的 Android 官方增强版，不扩展桌面版和多游戏引擎；
- 商业一致：继续采用免费预检、按项目收费、成功产出后核销、失败释放和维护期机制；
- 开源一致：不重新锁定已公开核心能力，增强价值来自规则、自动化、质量保障和支持；
- 安全一致：未知格式保守失败，不执行游戏代码，不用模型提示代替确定性验证；
- 隐私一致：API Key、完整 APK、剧情和完整译文默认只保存在本地；
